# PWA Shell (Fase P0 da migração web)

- Data: 2026-07-22
- Feature relacionada: F10 (FEATURES.md) — deriva da RFC-0001
- Status: em implementação

## Objetivo

Entregar o esqueleto do Lift+ como **PWA instalável no iPhone**: projeto
Vite+React+TypeScript, manifest + service worker (offline), pipeline de CI em Linux
e deploy no GitHub Pages. Sem features de produto ainda — o objetivo é ter uma base
instalável e um caminho de deploy funcionando ponta a ponta.

## Escopo

**Entra:**
- Projeto `web/`: Vite + React 18 + TypeScript (`strict`).
- PWA: `vite-plugin-pwa` (Workbox, `registerType: autoUpdate`), manifest com ícones,
  `display: standalone`, theme-color claro/escuro; `apple-touch-icon` para iOS.
- App shell mínimo: tela inicial com nome, aviso de "offline pronto" e estado de
  instalação.
- Camada de domínio inicializada (`src/domain/`) + Vitest com um teste de fumaça.
- CI web (`.github/workflows/web.yml`, runner Linux): typecheck + test + build e
  deploy no GitHub Pages.
- Filtro de caminhos no CI nativo (`ci.yml`) para não rodar o macOS em mudanças só
  de web.

**Fica de fora (próximas fases):** modelos de dados, telas de fichas/execução/
histórico, timer, gráficos — P1+.

## Design / abordagem

- **Estrutura** (RFC-0001): `src/domain` (puro), `src/data`, `src/state`, `src/ui`,
  `src/pwa`. Na P0 só `domain` e o shell em `ui`/`App` são materializados.
- **`base` do Vite:** `/lift-plus/` (GitHub Pages de projeto).
- **Ícones:** gerados de um SVG-fonte por script (`sharp`) nos tamanhos 192/512
  (maskable) e 180 (apple-touch-icon).
- **Offline:** Workbox faz precache do app shell; `navigator.storage.persist()` será
  solicitado quando houver dados (P1).

## Testes

- Vitest rodando no CI (Linux). Um teste de fumaça no domínio estabelece o
  encanamento; os testes de comportamento chegam com o port do `RunnerEngine` (P1).

## Riscos e decisões em aberto

- **GitHub Pages source:** requer habilitar "GitHub Actions" como origem em
  Settings → Pages (passo manual único do dono do repo).
- **Branch de deploy:** o deploy roda na branch de trabalho atual (default do repo);
  reavaliar quando `main` virar o default.
